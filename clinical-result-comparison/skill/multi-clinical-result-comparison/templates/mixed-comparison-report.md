## 九、完整证据附表（由渲染脚本生成）

本节（含标题与一行 `—` 图例）由 `scripts/render-facts.py` 从数值事实账本自动追加，**不要在正文里手写或改写附录、不要写标题/图例的占位符，也不要写一段描述附录版式的规格文字**：正文只负责把每个数字写成 `[[fact:<fact_id>]]` / `[[result:<fact_id>]]` 令牌，并维护账本文件。

渲染结果是一张跨披露对齐矩阵，**列与表头形态由渲染器固定，不要试图从正文左右它**：多试验输入 = **列 = 试验**（表头统一为 `**试验名**<br>注册号 · N 条披露`；`试验名` 取可读名——账本 `study` 名 → 记录 `trial` 名 → 身份行首段，注册号只作最后兜底，所以记录里有可读名时不要把注册号填进 `study`/`trial`；无注册号的试验显示其 `study`/`trial` 名；显示名本身就是注册号时只印一次 `**注册号**<br>N 条披露`。同一试验的多条披露按 `trial` 键合并）；**单试验输入且 ≥2 条披露 = 列 = 每条披露**（表头为 `**短版本标签**<br>{{ref_n}}`，没有可读标签时退为 `**{{ref_n}}**`），不再把同一试验的多条披露挤进一列用 `<br>` 堆叠。**行 = 维度与终点父级**；表内按「试验设计 → 试验结论 → 有效性 → 安全性 → PK/PD → PRO」分段，同一终点的不同时点或口径统一到同一行、细分标签写进单元格；整行一致的限定词上提到行标签（用 ` · ` 连接），单元格只留差异部分，格式为「治疗臂·时点·评估·人群：结果 单位（统计量）{{ref_n}}」，未报告写 `—`。长篇散文（题名、设计、试验组、人群与覆盖）**没有附录行**：设计/人群内容写在正文与「试验背景」表、用 `{{ref_n}}` 绑定即可，不要为它们花 token。账本里任何一条 fact 没进入该表、或令牌/引用/原文引文不一致，门禁失败并阻断交付；不得用删除附录或改用散文数字绕过。
