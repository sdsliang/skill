# 统计方法 (Statistics)

本文定义「会议临床解读」的统计维度和核心原则。统计是确定性的（脚本生成），模型负责**解读**这些统计、选择代表性证据、形成主题洞察，而不是重新发明数字。

## 1. 核心原则：热度 ≠ 记录数

会议中某药/某适应症"出现的记录数多"，只代表**曝光频率**，不代表**临床价值高**。原因包括：

- 大量记录是同一药物在不同适应症/线数/联合方案中的重复报告（如帕博利珠单抗 134 条）。
- 化疗辅药（奥沙利铂 109、卡铂 71、氟尿嘧啶 84、亚叶酸 68）作为联合方案常客，记录数天然偏高，但"热度高"不意味着"该药是会议亮点"。
- 记录数还会被试验设计（多臂、多终点）、更新版本等放大。

**因此**：
- 记录数分布只作为"会议覆盖面"的参考图（volumetric view），不得作为价值排序依据。
- 价值排序必须综合：评价质量（积极/不佳）、样本量、试验阶段、终点证据强度、是否代表新机制/新适应症、是否存在互补证据。

## 2. 统计维度（确定性）

由 `build-conference-stats.mjs` 生成，模型不修改这些数字，只引用：

| 维度 | 说明 | 用途 |
|---|---|---|
| `evaluation` | 积极/不佳/终止 分布 | 会议整体积极信号比例 |
| `trial_phase` | I期~III期 分布 | 研发成熟度 |
| `disease_stage` | 晚期/转移、早期等归一化分布 | 覆盖人群 |
| `indication` | 适应症覆盖 | 热点领域 |
| `drug` | 药物曝光频次 | 覆盖广度（非价值） |
| `biomarker` | 生物标志物曝光 | 精准医学热度 |
| `therapy_line` | 治疗线分布 | 布局阶段 |
| `endpoint` | 终点类型分布 | 证据类型 |
| `release_date` | 按日期/场次分布 | 会议日程热点 |
| `source` | 数据来源 | 完整性校验 |

## 3. 代表性证据选择（模型职责）

从 `evidence_scatter` 中挑选代表性证据时，遵循以下优先级（不纯看记录数）：

1. **III 期且评价为积极**（若有）——注册级/关键证据。
2. **大样本（sample_size 高）的积极 II 期**。
3. **评价为不佳/终止的高关注度试验**——负面结果同样重要，说明失败教训。
4. **机制新颖或适应症冷门**的记录。
5. **互补证据链**：同一主题（如某适应症）下的多个相互印证记录。

每个选中的代表性证据在报告中给出 `evidence_scatter[].id` 引用，并简述其 value（阶段/样本/终点/评价），不逐字转述全文。

## 4. 主题聚类（模型职责）

在统计分布之上，模型应形成 **3-7 个主题**（theme），每个主题：
- 由若干代表性证据支撑（引用 evidence id）。
- 说明为何"热度高/价值高"的判断成立（结合评价质量 + 样本 + 阶段）。
- 明确区分"曝光多但价值待定"与"价值已获证据支撑"。

主题示例方向：
- 免疫治疗在 XX 领域的密集布局（记录多，需看评价分布是否积极）。
- 某新机制/新靶点首次大规模 III 期数据（记录少但价值高）。
- 某适应症负面/终止信号（记录少但需警示）。

## 5. 信息缺失与局限

- `efficacy_text` 来自 `opt_dose_effect`，未覆盖全部记录的完整终点数值；报告中涉及的数值必须以 evidence 文本为准，缺失则标注"未报告"。
- `release_date` 可能缺失；发布日期分布缺省为 Unknown。
- 跨试验数值不可直接合并/池化；不做等效性推断。
- 样本量缺失的记录（`sample_size: null`）在按样本排序时排最后。
