--------------------------------------------------------------------------
1. 轮次背景
--------------------------------------------------------------------------
F1（`no tool errors` 断言在长 agentic run 里约 1/4 概率失败）三轮措辞强化（R43 扩覆盖面 →
R44 无条件 overwrite=True → R45 edit_file 收窄到报告正文）后基线未动，失败形态在
「`write_file` 漏传 `overwrite`」与「`edit_file` 陈旧 old_string」之间摆动。O42 给三个选项：
  A 接受为已知偶发
  B 改 runner：把「参数被拒、随后被平台重发成功」降为带预算的 WARN
  C 把正文改成「脚本从账本渲染一次成文」（减少写次数）
判定：A 单独使用等于把机械 flake 留在 keep/discard 信号里；C 是大幅行为改动、收益不明；
选 **B 的窄口径**：只收编两种**已被实测确认**的工具侧前置条件拒绝，且加预算闸门。

2. runner 改动（本地 CLI，可回滚）
--------------------------------------------------------------------------
文件：`~/.local/bin/toolsmith-publish`
备份：`~/.local/state/toolsmith-publish/toolsmith-publish.v15.bak`（先备份后改）
`diff` 结果 = 在 5 处新增 21 行、改 3 行，无其它改动：

  (a) 新增 `TOOL_REFUSED_RX`（第 ~746-758 行），`^` 锚定，只匹配两种已观测形状：
        write_file  `File '<path>' already exists. Read it first and use edit_file instead or
                     use write_file(overwrite=True) to replace it.`   ← R43-a、R45-14
        edit_file   `Could not find the target string in '<path>'`        ← R44-18
      加 `^` 的用意：被包装过的消息（`RuntimeError: File '/x' already exists`、
      `MCP error: …`）**仍然落 `errors`**（见第 4 节的负例测试）。
  (b) `retry_kind()` 对上述形状返回 `"rejected"`（此前落到 `"errors"`）。
  (c) 新增 `REFUSAL_BUDGET = 3`（第 ~760-762 行）。
  (d) 原本恒为 PASS 的信息性断言改成带预算的判定：
        旧： add(True, f"arguments refused by the tool (re-issued) = {len(st['rejected'])}")
        新： add(len(st["rejected"]) <= REFUSAL_BUDGET, ... + f", budget {REFUSAL_BUDGET}")
      ⇒ 断言条数不变（22），`verification.md` 语义不变，仍是一条 `[PASS]/[FAIL]`。
  (e) 注释同步（桶语义、预算理由）。

语义边界（写死在注释与测试里）：「工具自己因为前置条件拒绝参数」= 「schema 拒绝参数」同一类，
平台已按 `retry-prompt` 重发、模型已改道、run 正常完成；这属于**已恢复的调用**，不是失败。
但**每次 run 最多容忍 3 次**——4 次以上说明模型在系统性误用某个工具的参数，必须整 run FAIL。

6. 残余风险与回滚
--------------------------------------------------------------------------
风险 1：把工具侧前置拒绝整体降级，理论上会掩盖「模型反复用错某个工具」的真实缺陷。
        缓解 = 预算 3 次/run + 双形状 `^` 锚定 + 负例测试；历史最坏样本为 2 次。
风险 2：若平台改变 re-prompt 文案（例如改写 `already exists` 措辞），正则失配 ⇒ 该 run 回到
        旧口径（判 FAIL）——即**失败方向是保守的**，不会漏判，只会重新变严。
回滚：`cp ~/.local/state/toolsmith-publish/toolsmith-publish.v15.bak ~/.local/bin/toolsmith-publish`
      + 重跑 `evals/runner-gate/test-runner.py`（应回到 38 tests）。未触碰 prompt / Skill / dist，
      ToolSmith 上无任何写动作。
