## 1. 体检：重在哪、慢在哪（两本账要分开）

三次真跑（同输入 4 esid，DeepSeek Flash）的运行期构成：

| 口径 | 数值 | 含义 |
|---|---|---|
| 我们的 skill 占上下文 | **20,347 tok = 16%** | 平台工具 schema **85,995 tok = 69%**，MCP 5,927，通用系统提示 27,438；cache 命中 **97.4%** |
| 生成占墙钟 | **91–93%** | 工具执行合计仅 5.0–6.7 s（1.5–2.0%） |
| 生成里「思考」 | **65–71%** | 落笔（真打字）10–12%，每步固定开销 11–16% |

⇒ **减字节 ≠ 提速**（时间花在 output token，且主要是 reasoning）。反过来，**减步数才省时间**：
同输入 19 步 / 251.7 s vs 29 步 / 354.5 s。

**真正的缺陷是「权重↔热度错位」，不是「字太多」**：prompt 把 21% 的字节花在 `## Subagent delegation`
（7,838 字符）与 `## Step discipline`（9,050 字符），而这两处在本项目三次跑里的**思考命中率是 0.00–0.01/千字**——
即「被遵守、但不被推敲」。它们不是冗余，是**防错契约**：下游门禁 fail-closed，删掉散文 = 把「预防」换成
「下游发现 + 返工」，**反而更慢**。这是本轮最重要的一条结论，也是为什么不能"哪里长就删哪里"。

## 8. R62-1：一次静默失败如何变成 18 次调用（`r62-14` 的第 33–50 号调用）

**触发**：模型把一段自我修复旁白写进了**交付正文**（`artifacts/output/report.md` 第 95–97 行）：

> `Hmm, I wrote "[[fact:j5]] 剂量组中出现 5 起轻度注射部位事件，见于 [[fact:j8p]]" — that's wrong: j5 is Cmax 667 ng/mL, and j8p doesn't exist. Let me fix that row…`

其中 `[[fact:j8p]]` **不存在于账本** ⇒ `render-facts.py` 校验失败（`unknown fact token`，第 276 行）。

**代价链**：第 29/32 步 `render-facts.py` 只得到 **`RENDER_EXIT=1`**（无任何原因）⇒ 模型转而 ① `head -n N` **二分报告**（7 次：n≤94 过 / n≥96 挂，逐段试渲染）、② `--help` 钓鱼（1 次）、③ `runpy` + `traceback`（2 次，含读脚本源码）——**共 ~18 次调用 / 28% 步数**；第 53 步 `patch.py` 删掉那 1 行后 `RENDER_EXIT=0` 恢复。

**根因（已复现，两个缺陷叠加，都在我们这一层）**：

1. **脚本静默**：失败原因只写进 `audit["errors"]`（`render-facts.py` 第 812/814 行），`main` 直接 `return 1`（第 835 行）⇒ **stdout 0 字节 / stderr 0 字节**。复现：

   ```bash
   printf '# t\n\n数值 [[fact:NOPE]]。\n' > /tmp/probe.md
   python3 -B skill/multi-clinical-result-comparison/scripts/render-facts.py \
     --ledger <真账本> --draft /tmp/probe.md --out /tmp/o.md --audit /tmp/a.json
   echo "EXIT=$?"   # → EXIT=1，且 stdout / stderr 皆空
   ```

   实测 stderr 输出处数：`make_chart` 16 / `make_citations` 15 / `build_ledger` 13 / `patch` 10 / `prep_sources` 7 / `check_report` 2 / `tell-scan` 1 / **`render-facts` 0** —— 最 fail-closed 的那个恰好唯一不报错。

2. **我们的文档教了吞掉退出码的写法**：prompt / SKILL.md / `references/toolbox.md` 中 `2>&1` 出现 **0 次**；`toolbox.md` 第 276 行样板 = `check_report.py -v 2>&1 | tail -40` 后接 `echo "CHECK_EXIT=$?"` ⇒ `$?` 取到的是 **`tail` 的 0**。实测该跑 `CHECK_EXIT=0`，而**同一份输出里就有两行 `FAIL:`**，其中一行直指 `unresolved fact/result token(s)` ⇒ **模型当时已经拿到诊断，被假退出码掩盖**。

**修法（R63 单一假设，全在我方层）**：① `render-facts.py` 返回 1 前把 `audit["errors"]` 逐行打到 stderr，`test-render-facts.py` 加断言「未知 token → exit 1 且 stderr 非空」；② 样板改 `2>&1 | tail -20; echo "EXIT=${PIPESTATUS[0]}"`，并写明「非 0 退出先读 stderr / `work/audit.json` 的 `errors[]`，**禁止**用 `head -n` 二分输入、`--help` 钓鱼、`runpy` 取 traceback」；③ 交付物禁自我旁白（触发源）。**预期：18 次 → 1–2 次调用，按本轮 3.16 s/步计省 150–200 s（≈ 该跑 22–30%）。**
