# Clinical Result Comparison

Tool Smith project assets for source-grounded synthesis and comparison of multiple selected clinical result records. The default output is a trial-level evidence synthesis for same-trial selections and a comparison-first, domain-aligned cross-trial comparison for mixed selections, each with a compatible chart when the data allow it.

## Product boundary

- Input is delivered as a **selected esid list**: the frontend sends each selected clinical result as its clinical-result esid (`clinical_result.extra_esid`) in the user turn. The Agent pulls the detail records itself through the MCP tool `pharmcube-query-clinical-result-with-params`, passing `extra_esids` plus a strict, minimal `selected_fields` allowlist (names copied verbatim from ALLOWED_FIELD_NAMES in `docs/params-tool-schema.md`). Clinical evidence comes from the pulled clinical-content fields (`abstract_text`, `summary`, `study_results`, design/arms context); `paper_title`, `full_article_link`, `paper_release_time` are citation metadata; entity fields (`projects.associate_ids`, `trial_abbreviation`, `arms[].drugs[].drug_earth_id`, `projects.company_ids`) are display/label metadata for inline entity references only.
- The backend/frontend supply only the selected esids; the Agent never fabricates, guesses, or retrieves URLs, IDs, or records outside the pulled set. Runtime identifiers and retrieval/storage details remain outside the Agent request and report.
- Per-esid mapping keeps large selections (20–50 results) addressable; a strict `selected_fields` set bounds the returned payload (a full record or a huge response can exceed the context budget). Input (esid) order defines `{{ref_n}}` assignment. Input order is a presentation label, not clinical chronology.
- Runtime identifiers and retrieval/storage details remain outside the Agent request and report.
- The primary analysis object is the underlying trial. Multiple disclosures from one trial are source nodes that are deduplicated into a longitudinal evidence chain covering design, efficacy, safety, maturity, and information gaps.
- Every material number and source-dependent conclusion carries an internal citation token for rendering; the user-facing report shows numeric superscripts. Citation metadata is emitted separately as strict JSON, with `title`, `link`, and `paper_release_time_str` per ref.
- For mixed inputs containing different trials, the deliverable is comparison-first and domain-aligned: efficacy, safety, PK/PD, and PRO are aligned across trials so the user can judge which treatment is better or worse, with explicit comparability/evidence-strength labels and compact per-trial context. The report does not pool results or fabricate head-to-head proof. `{{ref_n}}` numbering is global across the complete response and the separate citation JSON is shared; numbering resets only when the runtime explicitly requests separate independent reports.
- Version 1 uses only selected results and performs no external retrieval.
- The frontend may render each marker as a numeric superscript link using the final JSON. It must preserve exact supplied URLs and use safe external-link attributes.
- The backend/frontend enforce a conservative real-time token budget.

## v0.14 changes

- **Deliverable file names are now fixed, so the backend can hard-code them.** The previous `<slug>`-based naming (descriptive prefix chosen by the model) is gone: the report is always `/workspace/output/report.md`, the citation JSON is always `/workspace/output/citations.json`, and chart products are always `/workspace/visualizations/evidence-timeline.json` plus `/workspace/visualizations/endpoint-bar-<n>.json` / `/workspace/visualizations/endpoint-line-<n>.json` (`n` = that kind's order in the report, from 1, so a lone quantitative chart is always `endpoint-bar-1.json` or `endpoint-line-1.json`). The chart kind is in the file name **and** must match the JSON `type` field, because the renderer dispatches on `type` (`bar` / `line` / `timeline`). The backend no longer reads the path back from the `present_artifact` result. Reruns overwrite these files in place — one current report per workspace, matching the platform rule that a presented path means "the current version of this path". Trade-off: the artifact card and the download name become `report.md` (no `display_name` parameter today) and earlier reports in the same workspace are overwritten.
- **v0.13 abandoned; v0.14 is built on the v0.12 baseline.** The lightweight quick-comparison variant is kept on disk for reference (`docs/legacy-v0.13/`, `dist/multi-clinical-result-comparison-v0.13.zip`) but is no longer the shipped Skill: the shipped bundle returns to the v0.12 full-synthesis assets and report templates.
- **TEMP dual-write removed; `::visualization` references point back at `.json`.** The renderer is being integrated, so `references/chart-templates.md`, `references/timeline-diagram.md`, `SKILL.md`, the report templates and the system prompt no longer emit or mention a `.preview.html` twin; `templates/charts/render-preview.py` moved to `docs/legacy-html-charts/` (that archive directory was itself deleted in v0.15).
