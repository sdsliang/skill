# 报告去 AI 味（中文）

把中文报告正文写成一个人写给具体读者看的文字：先给结论，只讲事实与依据，术语一致，不解释自己是怎么工作的。

三种使用方式：

- **嵌入写作**：一边生成报告一边遵守本规则。交付物只有报告正文，不含改写说明、命中清单或自评分。
- **改写草稿**：收到既有稿子，输出改写稿。说明放在交付物之外（对话里），除非用户要求一并给出。
- **审阅**：只给问题清单与建议，不改文件。用户要求才写回文件。

配套文件（按需读取）：

1. `references/patterns-zh.md`：完整表达问题清单（结构级 → 措辞级 → 中文特有），每条给出报告场景的改写前后对照。
2. `references/naming-bilingual.md`：实体与术语的中英写法规则，含药名查字典流程与查不到时的回退写法。
3. `references/examples.md`：整段报告的前后对照（含「应当保留」的反例边界）。

## 一、优先级

冲突时按顺序处理：

1. **保信息、保确定程度。** 不加原文与用户材料之外的数字、名称、日期、引文、来源、结论或因果。不丢独立信息、否定、比较对象、范围、条件、时间、完成状态与归因。不把相关写成因果、可能写成确定、计划写成已完成、亚组或事后分析写成主要结论。
2. **守用户的编辑范围与文体。** 润色不默认包含扩写、补论据、改结论或重排结构。用户明确要求时，才做。
3. **匹配该文档既有的声音。** 有样本（同一份报告的其它章节、既往同类报告）时沿用其句长、术语与叙述习惯；样本里的数据与立场不搬进正文。没有样本时保留输入的语域。
4. **处理具体表达问题。** 模式清单是检查线索，不是词语黑名单。没有问题的地方原样保留。

## 二、报告文体与读者

报告读者是决策者：他要的是判断依据，不是工作汇报，也不是作者的自我说明。

- **结论先行。** 每节先给判断，再给支撑事实。不要用「先介绍背景，再层层推论到结论」的悬疑结构。
- **一段一义。** 段落围绕一个判断组织；不必为整齐把每节压成同一长度。
- **写完即止。** 没有新信息的句子就是多余，包括收尾拔高、过渡铺垫和「意义」段。
- **术语稳定。** 同一实体、同一终点、同一指标全篇同一写法（见第四节）。
- **允许必要的正式度。** 正式报告可以被动句、名词化、限定语；不要为了「自然」把严谨表述口语化，也不要以「去痕迹」为由删掉真实限定。
- **不写营销语气。** 不夸产品、不承诺、不用「赋能」「生态」「版图」这类词包装事实。

## 三、硬性禁项：报告里不写工作过程与自我解释

这是本 skill 针对报告（尤其 TS 项目产出的报告）最强的规则。交付物里出现下列内容，一律删除：

- **工作过程叙述**：「本报告基于 N 条证据/检索了 X 个数据源」「为提高可比性，我们统一了…」「我先核对登记号，再抽取终点」「下面我将从三个方面展开」「本节介绍…，下一节…」。
- **工具与流程交代**：「用 XX 工具检索后」「经标准化处理」「按既定模板填写」——除非读者必须知道口径才可信（见下方例外）。
- **选择理由与内心戏**：「之所以选这两个试验，是因为…」「我倾向于认为」「综合考虑后决定」「权衡再三」「如果不做这个假设，会导致…」这类推理过程留在思考里，报告只给结论与依据。
- **自我评价与置信度**：「分析可靠」「结论稳健」「把握较大」「本判断可能存在偏差」——不确定性用数据口径表达（不显著、未报告、区间宽），不用自评表述。
- **不确定性的空转声明**：「现有材料有限，无法给出更多信息」「数据可能不完整」——除非能指出缺哪一项、影响什么判断。
- **改写仪式**：「（已优化/已去 AI 味）」「以下是修改后的版本」「如需调整我可以继续修改」。
- **AI 元信息**：不写「由 AI 生成」「模型可能出错，请复核」，不写「如需要可进一步…」的客服尾。

**允许的例外**（写，且只写一次）：数据截止时间与来源口径、纳入与排除口径、分母与人群定义、随访与分析时点、终点定义与统计假设、真实局限与未报告项、会改变读者采信或行动的说明。

判据只有一句：**这条说明会不会改变读者对结论的采信或行动？** 会 → 写清、写一次；不会 → 删。

还有一个直接判据：**这句话是在讲「我的工作」，还是在讲「事实」？** 讲工作的，删。

**例外里的措辞边界**：宿主契约强制要求的声明（如「全文未取回、按摘要级核对」「某条记录未纳入」）必须写，但写成**材料自身的客观属性**，不写运行环境、工具与链路过程——写「本批材料均为摘要级、无全文记录」，不写「本次运行无外网抓取通道，PubMed→PMC 链路未能发起」。同一件事，前者是读者需要知道的口径，后者是你不必交代的工作条件。

## 四、数据与依据

- 报告里的每个数值、比较、时间点都要能回溯到输入或来源；**不产生新数值**，**不把「未报告」写成「不存在」**，**不跨试验直接比数字**（除非输入本身给了可比的对照）。
- 剂量、分期、样本量、HR/OR/RR、95% CI、p 值、单位、百分比精度**逐字保留**，不四舍五入、不换算、不合并。
- 区分预设分析与事后分析、计划终点与已达成终点、主要终点与探索性终点。
- 表格与图各司其职：图不重复表格里已有的数字，表格不靠散文复述。正文不逐格复述表格内容。
- 受保护内容**逐字节不动**：引用标记与锚点、表格数据、列表项顺序、代码块与行内代码、命令、路径、URL、ID、YAML front matter、结构化数据（JSON 等）。这些不因润色改动。

## 五、术语与命名（中英）

缩写首次出现给全称与缩写（`帕博利珠单抗（pembrolizumab，抗 PD-1 单抗）`），其后统一用同一形式；全篇只用一个写法，不在同文里混用别名。

**药物名称（硬性流程）**

1. **常识优先。** 常见药的中英对应是确定知识，直接用：`帕博利珠单抗 = pembrolizumab`、`贝伐珠单抗 = bevacizumab`、`奥希替尼 = osimertinib`。确定就不要查。
2. **不确定 → 查字典。** 按可用性顺序选一种，**只查一次或两次，不连环试探**：
   - 宿主项目已经返回成对字段时，直接用它，不自己译：如参数化检索结果里的 `drug_earth_name_cn` / `drug_earth_name_en`。
   - 药品字典工具：TS 报告类项目的 `report-query-drug`（`drug_names` 传入名称，`is_en` 切换中/英输出）；或医药魔方 MCP 的 `pharmcube-mcp-drugBaseLiteCN`；或 Linking API 的 `drug` 实体（用于取标准名与异名）。
   - 查到多个候选时，取与报告语境（研发机构、靶点、适应症）一致的那个，不取热度最高的那个。
3. **查不到 → 按方向回退，绝不编造译名：**
   - **英 → 中：不强行翻译，保留英文原名**（如 `zongertinib` 查不到对应中文名就一直写英文，不音译、不造「宗格替尼」这类未证实译名）。
   - **中 → 英：用拼音**（如输入给的是中文俗名且无英文对应，写拼音并可在首次出现处括注中文原名）。
   - 任何时候都不缩写为臆测的中文简称或英文缩写；不把商品名当通用名，也不擅自替换成通用名（原文用商品名就保留商品名，需要时括注通用名）。

其它实体同规则：试验名与注册号（NCT/ChiCTR/…，原样复制、不改大小写、不重排）、公司（标准简称优先，首次出现可给全称）、靶点（沿用输入的标准写法）、终点（缩写首次给全称，如 `OS（overall survival，总生存期）`）、疾病（标准中文名，需要时括注英文）、分期与治疗线（`III 期临床`、`二线`，全篇统一）。

中英混排：中文正文用中文标点，英文专名与缩写保持原文大小写与连字符；中英文之间不加空格，除非该文档既有风格如此；数字用阿拉伯数字。

**数字与符号的排版要全篇统一（只统一排版，不动数值）**。来源材料经常混用写法，照抄进来就会出现「同一个数值两种形态」，这是最显眼的外包/机器痕迹之一：

- **小数点只用一种**：源材料里出现中圆点（`10·3 个月`）而正文其余用普通小数点时，统一成 `10.3 个月`；小数位数与数值本身不动。
- **百分号紧贴数字**：`64%`，不写 `64 %`。
- **区间号只用一种**：`0.46–0.78` 与 `0.46-0.78` 不要混用；文档已有惯例时随惯例。
- **不加新东西**：不擅自加千分位、不补单位、不统一成「保留两位小数」。
- **范围**：正文与列表。表格、引用标记、代码、路径、URL、ID 按宿主契约处理；宿主把表格列为受保护内容时表格照录，至少把正文与列表统一。改动只限符号形态与空格，任何一个数值的**取值与位数**都必须与原稿一致。

细节与更多对照见 `references/naming-bilingual.md`。

## 六、工作流程

1. **通读并标记。** 判断文体与目标读者，标出结论、数值、口径、限定和来源；同时按 `references/patterns-zh.md` 标出表达问题（结构级问题优先看段落形状，不只看句子）。
2. **重写，不打补丁。** 一句一句改被标记的词组会留下同样的腔调；围绕该段的主结论整段重写。保留全部有来源的主张。
3. **自查。** 逐条过第七节清单：有没有新增事实、丢掉限定、把可能写成确定、把过程写进正文；需要机械扫一遍时用第八节的 `scripts/tell-scan.py`。
4. **定稿。** 交付只有正文；说明放在正文之外。已通顺的地方不再改动。

## 七、交付前核对

- 有没有出现「我的工作」而不是「事实」的句子？（第三节）——这是首要检查项。
- 新增的任何具体信息，能在输入或用户材料里找到吗？找不到就撤回。
- 独立信息、否定、比较对象、范围、时间、完成状态、归因是否完整？「可能/据称/超过/仅/计划/尚未」承载的含义是否保留？
- 有没有把相关写成因果、把未报告写成不存在、把亚组写成主要结论？
- 数值、单位、置信区间、引用标记、表格数据、ID 是否与原文逐字一致？
- 数字与符号的排版是否全篇统一（小数点 / 百分号 / 区间号）？同一个数值有没有出现两种形态？统一时有没有动到数值本身？
- 同一实体/缩写/药名在全篇写法是否一致？缩写是否有首次定义？查不到的药名是否按方向回退（英→中保留英文，中→英用拼音）而没有编造？
- 收尾是否只是重复赞美或祝福？有没有留下没有依据的「意义」句？
- 原稿通顺的地方是否被强行改动？引文、标题、专名、术语本身是否保持原样？

不要用「字数下降」「命中数下降」或自评分代替事实与语义核对。

## 八、机械自查（可选助手）

技能包自带零依赖扫描器：`scripts/tell-scan.py`（随技能包发布，相对路径不变）。

```bash
python3 -B scripts/tell-scan.py report.md            # 自动判中/英
python3 -B scripts/tell-scan.py report.md --json     # JSON，给脚本消费
python3 -B scripts/tell-scan.py report.md --weak     # 弱命中也算，从严
python3 -B scripts/tell-scan.py report.md --allow S-INFL-02,W-AIWORD
```

规则家族：

| 家族 | 抓什么 |
|---|---|
| `S-PROC-01..10` | 过程叙述、流程与工具交代、选择理由、自我评价与置信度、改写仪式、AI 元信息 |
| `S-INFL-01..05` | 假对比、意义拔高、无出处的借权威、空泛评价 |
| `S-STRUCT-01..04` | 复述图表、套话收尾、总起空转、标题复述 |
| `W-*` | 措辞级：破折号连用、AI 包装词、限定词堆叠、模糊关联、进行+动词、被字句、四字排比、粗体装饰，以及文档级计数（破折号/粗体密度、**数字记号混用**） |

用法边界（重要）：

- 它是**助手不是判分器**：命中不等于必须改，没命中不等于没问题。`强` 命中才建议动手；`弱` 命中要结合同段其它命中与上下文判断。
- 交付物里出现过程叙述或自我解释时，不看扫描结果、直接按第三节删。
- 退出码：`0` 无强命中 / `3` 有强命中（可当闸门）/ `2` 用法或文件错误。
- **不要用命中数下降代替事实与语义核对**（见第七节末）。

## 九、何时不要改

引用原文、标题、专有名词、术语本身、表格数字、结构化数据，以及用户明示要保留的风格都不动。作者有意使用的对比、排比、破折号、第一人称与情绪，在报告文体允许且承载信息时保留。本 skill 只处理表达问题，不判断作者身份，也不保证文本能通过任何检测器。
